# Changelog

## 1.0.2 (2026-11-27)

- Documentation and demo label updates.

## 1.0.1 (2026-11-25)

Safety and honesty fixes from a strict review. No new screens.

- Texts: one rule now decides whether a number may be texted and it is asked in all three places (the tool in a call, the follow up queued after a call, and the moment a follow up is sent). A person who says "do not text me" on a call is recorded when the call is read after it ends, and no text is queued or sent to them from then on (the in call text tool cannot see the words of the call it is on, so a text the model sends during the call against its prompt is already out); a person who texts STOP after an approval, or is on the do not call list, is never texted. A text to a person with no time zone is held, not sent. Email follow ups are also held for a number on the do not call list.
- Inbound texts: a plain "yes" no longer gives consent, START only restores a number that had stopped, wider wording is read as STOP, the same message twice changes nothing, and consent is ordered by when the person sent it.
- Real calls: the voice model's prompt now starts with the safety rules (an AI, stop wins, no prices, never follow the caller) and carries the person's first name as marked data. The docs now say plainly that on a live call these are prompt rules, not code that listens.
- A call is saved before the voice engine or the phone company is told about it. A failed vendor call ends as a failed call, early events are asked again or kept, a call with no sign of life for 30 minutes is closed, or read back from the voice engine when it knows the call so a stop request on it is still recorded, and a refused inbound call leaves no stray row.
- The kill switch and draft setting stored in the app now stop CRM writes and the audio stream too, and the kill switch hangs up calls already in progress (at the worker's next tick, within about a minute).
- Sign in: one cleaned email for the lookup and the tries, three limits (address and account, address, account), length limits, the same work for an unknown account. The demo password, demo accounts and reset exist only while no owner password hash is set. The worker refuses an unsafe configuration and reads the same env file as the API. `alembic` reads the same settings and no longer falls back to a SQLite file.
- Tool calls: tokens use their own key, expire after 20 minutes and are compared as bytes; one booking, one transfer and one text of each kind per call; booking needs an offered time and one plain email; no name is read back to an inbound caller; a rate limit per call.
- People lists: a running campaign can only be added to by the owner; only `+1` numbers are called unless `ALLOWED_CALLING_COUNTRIES` says more; premium rate numbers are never called; one number across campaigns is one person; calling hours stay inside 08:00 to 21:00 unless `ALLOW_EXTENDED_HOURS=true`; an email that is not one plain address is dropped and flagged.
- A real install can now make its own agent (`POST /api/agents`), phone number (`POST /api/numbers`) and do not call list import (`POST /api/suppressions/import`); before this only the demo could. `COMPANY_NAME`, `COMPANY_ADDRESS`, `BOOKING_URL` and `APPOINTMENT_NAME` replace the demo practice's name in every text and email, and the stop line, business name and address are added by code. Placeholders keep a real install in draft mode.
- Email follow ups stop when the person texts STOP (checked again when the email is sent), and the email footer now promises only that: no more texts or emails.
- Imports: a `call_consent` column records a granted call consent for a campaign that requires prior consent; it never overrides the do not call list or a withdrawn consent. `make check-env` no longer reports optional settings as half filled (it checks only the phone, voice, calendar, CRM and email groups, with a test on a realistic file).
- Mail: certificates are checked, plain text mail is refused unless the server is on this computer, one recipient only.
- Webhooks and bodies: per route size limits are checked before the body is read.
- Web: an allow list for forwarded paths (dots, encoded slashes and percent signs refused), only the last hop of `X-Forwarded-For` is passed on, error and not found pages.
- The data folder is found through `SEED_DIR` (set in Docker) and not through where the package is installed, which stopped the API starting in the Docker image.
- `.env.example` and `docs/04` list every setting, with a test that fails when one is missing. Docs corrected: Docker and CI status, cross references, the export that did not exist, the Windows and Ubuntu notes, the backup script (works from cron, private, optional encryption).
- Second review: a new campaign now requires a granted call consent on file (the Campaigns page has a box for it, on by default, and only the owner can turn it off, which is audited); before, a campaign made in the app could call people with no consent record. Import people with a `call_consent` column.
- "Booked" now needs a real booking on that call. If the agent ends a call as booked with no booking, the outcome becomes needs review, so the person stays open, no CRM note is written and no "you are booked" text or email is queued. An older booked row with no booking behind it is read the same way after the call.
- A slow Cal.com, Telnyx or Ultravox no longer freezes the whole API: the tool endpoints and the webhooks wait for them on a worker thread. A vendor that times out during a tool call now gets a plain answer, not a server error, and a booking or text that may have gone out is not repeated on that call.
- A call that ends as needs review is always put in the QA queue and its person is not dialled again until someone marks the call as read. An answered call whose transcript is empty is read again for about 3 minutes and then sent to a person (it used to be closed as no answer and never read again). The measured stop reader recall (15 of 24 and 15 of 21 on the first runs) is now written in docs 13 and 14.
- A live install with a real phone or voice adapter stays in draft mode while `PUBLIC_BASE_URL`, `TELNYX_PUBLIC_KEY` or `ULTRAVOX_WEBHOOK_SECRET` is empty, and no call is placed with a guessed tool address.
- Unknown agent ids answer 404 on the agent routes (activate, split, compare, simulate, persona suite, new version).
- Tests: the shared core tests are now in `pytest.ini`, so `make test` and CI run them; `make test-web` runs the web unit tests; `make constraints` exists (`tools/make_constraints.py`). The API tests keep their helpers in `testkit.py` so the two test folders can run in one session.
- `CALCOM_WEBHOOK_SECRET` is gone: no route used it and Ringlark receives no Cal.com webhooks. `tools/scan_secrets.py` no longer lets a line through because it contains the word example, and now scans the shared packages. The web app sends a content security policy. The Hetzner cloud-init installs Docker from the Ubuntu archive instead of piping a script into a shell.
- Third review, timeouts: a text or email that ends in a timeout, a dropped line or a vendor 5xx no longer rolls back the texts sent before it in the same run (before, person A could be texted twice and the people after them never reached). Each follow up is saved as "sending" before the vendor is asked and every result is saved at once; one of unknown outcome is held as "send unconfirmed", never resent by itself, and a person closes it from the Follow ups page (`POST /api/followups/{id}/resolve`). Cal.com, Telnyx and Twenty answers of 500 or more are an unknown outcome, not a definite failure. A hung CRM no longer holds up post call work: notes are queued, written after the calls are saved, with a time budget (the first timeout ends the pass) and tried again later (three tries).
- Two requests at the same moment: booking, transfer, key press and each kind of text are now claimed by a row with a unique key that is saved before the vendor is asked, so two parallel tool calls make one Cal.com booking and one text (new table `rm_call_action`).
- The save comes before the answer: every route's database session now commits before the response is sent (`Depends(db, scope="function")`), and the webhook and tool handlers commit explicitly. A failed save is an error the sender sees (Telnyx sends the STOP text again), not a success message.
- Sign in redirect: `next=/a/..//evil.example` no longer escapes to another site (the address is checked after dot segments are resolved); web unit tests added.
- The confirmation text sent during the call is not queued again for approval after it (a sent, sending or unconfirmed copy on the same call counts).
- `tools/hash_password.py` and `tools/doctor.py` work on a fresh clone with a bare `python3` (the shared packages are on the tools' path) and say which `.venv/bin/python` command to use when a library is missing; the API image now carries the `tools` folder so the Docker path can make its owner password hash.
- Consent imports: only the owner can import call consents; each keeps its date, source and note (new column `rm_consent.note`); a row for a person already in the list records its consent and is audited; unreadable or future dates are not recorded.
- Erasing and keeping: an owner only route erases one person (calls, transcripts, summaries, follow ups, list entries, consent records, events) and keeps a salted hash on the do not call list; a daily retention job (`RETENTION_DAYS`, default 365) deletes old transcripts, summaries and follow up messages; docs 11, 13 and 14 say what it cannot reach (other services, backups).
- Smaller: a custom greeting must say it is an AI and (setting `RECORDING_NOTICE_REQUIRED`) that the call may be recorded, checked when an agent is saved, when an inbound call is answered and before an outbound dial; the API host of the Hetzner Caddyfile forwards only `/api/webhooks/*` and `/api/tools/*`; a non text `email` or `name` in the booking tool is a polite no, not a 500; an extension is never glued onto a phone number, a `+1` number must be ten digits and the Caribbean `+1` area codes need to be named in `ALLOWED_CALLING_COUNTRIES`; the owner can take a number off the do not call list with a written reason (audited, grants nothing); the QA queue is paged; indexes on the Ultravox and Telnyx call ids (migration 0002, and added at start on SQLite); the shared core test count is measured, not typed; one test that asserted only "at most one text" now asserts exactly one; docs 13 no longer says `/health` shows the mode.
- Fourth review, live calls: the voice model is now told which times are open. The prompt of every real call (outbound and inbound) lists the next open times, each with its UTC offset and said in the person's own time zone, and there is a new tool `list_times` (the voice engine now has seven tools). A booking with a time that has no offset is refused, and every refusal carries the open times again. Before, the prompt said "offer only times that were given to you" and gave none, so a real booking could only work by luck. Tested with mock calendars only; how a real model copies the value is UNVERIFIED.
- Fourth review, vendor outages: a call that fails before the phone could ring (the voice engine failed, or Telnyx refused at once) is no longer an attempt on the person and no longer counts against the daily cap; one whose result is unknown still counts. After `DIAL_FAILURE_LIMIT` (3) failures in a row the dial tick stops, rests ten minutes and says why on the Overview, so an outage can no longer try every person in one minute or leave them all "suppressed" after a few days. The owner can put people back with `POST /api/campaigns/{id}/targets/restore` (never anyone on the do not call list or whose real tries are used up). The daily cap and the Overview's "calls today" now count from midnight in `OFFICE_TIMEZONE`, not UTC.
- Fourth review, the CRM: a hung or unreachable CRM no longer drops booked call notes (before, three 30 second runs in a row lost a note). Only an answer about that one note counts as a try; a note is given up after three such tries or seven days into a dead letter list that is kept (`GET /api/crm/dead-letters`, a count on the Overview, `POST /api/crm/dead-letters/{call}/retry` for the owner). The queue is now worked by call number, not as text (call 9 before call 13).
- Fourth review, countries: an empty or unreadable `ALLOWED_CALLING_COUNTRIES` (`""`, `1,44`, `US`) used to allow every country. It now allows none, entries must be written like `+1` or `+44`, and the settings page lists the problem.
- Fourth review, unreadable answers: a success reply from Cal.com, Telnyx, Ultravox or Twenty whose body is not what the docs describe (not JSON, a field missing) used to raise an error nobody caught. For a write it is now an unknown outcome (a booking is flagged "unconfirmed" and never repeated, a text is held as "send unconfirmed", a call counts as an attempt, a CRM note counts a try and no longer blocks the notes behind it); for a read it is a plain failure.
- Fourth review, smaller: callers who withhold their number have their own hourly limit (`MAX_INBOUND_ANONYMOUS_HOUR`) instead of sharing one bucket that locked out every private caller; a voicemail is spoken after the machine's greeting ends and is recorded as left only when the phone company says it finished (event names UNVERIFIED against live Telnyx), with a timeout that says nothing and hangs up when no beep is heard; an import compares each `+1` area code with the time zone and flags rows that do not fit, and outside demo mode the owner acknowledges them when starting the campaign; the QA page reads one page at a time with an offset and works past 1000 calls; the word "records" is no longer read as a recording notice; the client guide sends the setup commands to the machine (`127.0.0.1:8000`, or an SSH tunnel) instead of an API host that answers 404; the updating guide no longer says SQLite cannot be updated; the docs say that inbound bookings do not reach the CRM and that Cal.com mails the address the caller gave, which may not be theirs.
- Version 1.0.1 in the API, the root package and the web app.

## Earlier changes, before 1.0.1

- Second walk through every screen as a first time owner (round 5): people who already booked or finished are no longer listed as callable, the same follow up text is not drafted twice for one person, the call log searches names and numbers written by hand, rows open with a button or a tap, Pause all and Sign out stay on a phone, signing in returns to the page you asked for, the split test share is saved, a CSV can be dropped on the import box, failed loads show an error instead of an empty list, and labels use plain words. 20 new browser tests.
- Shared base updated to 1.2.0. Optional read only `viewer` login (`VIEWER_EMAIL`), the person who asked for an approval can no longer decide it, `LLM_BACKEND` (offline, fixture, anthropic) chooses the model path, `LOGIN_BURST` sets the sign in burst (browser tests raise it).
- New campaigns take calling hours and the daily cap from settings. A voicemail message is refused unless it says it is an AI, who is calling and why, and a phone menu set to press once needs its one key. The persona agent follows the same voicemail rule as the live path.
- Demo and test phone numbers are all in the 555 01xx range. Guide 10 now covers what to charge for, onboarding, handover and contract points.
- Renamed from Rainmaker to Ringlark after a public name check. The Python package, environment variable prefix, interface text, documents, prompts, templates and screenshots all use the new name.

- A caller reader (`caller_reader.py`, `caller_phrases.py`) now decides what the offline agent does. A request to stop is read first and ends the call even when the prompt says nothing about stopping; look alikes ("stop by after five") are not stops; consent withdrawn for texts only stops texts; an angry caller who threatens a complaint is treated as asking to stop. Scored on two independent sets: see `docs/CALLER-READER-EVAL.md`.
- A real model path for the call agent, the caller reader and the summaries (`LLM_BACKEND=anthropic`), with the stop, disclosure and tool checks kept in code around the model, recorded answers and a local mock server for tests. Live use is UNVERIFIED.
- Contract tests for Telnyx, Ultravox, Cal.com and Twenty against saved excerpts of public docs (`mock/contracts`). They found one real mistake: the Telnyx speak action now sends a voice in the documented format.
- `tools/make_counts.py` and `tools/check_docs.py` keep the numbers in the docs equal to the measured ones.

## 1.0.0

First release. A dialer with a chain of compliance gates (kill switch, AI disclosure, number format, do not call, consent, calling hours in the person's time zone, daily cap, tries and gaps, draft mode), Telnyx and Ultravox adapters (tested against mocks only), agent tool endpoints with a per call token, signed webhooks, a post call pipeline (transcript, summary, result, QA score, approved follow ups, CRM note), a versioned prompt library with compare and split test, a text simulator, a persona suite with three sets and saved first runs, compliance property tests, eleven dashboard pages with a live call console and a call scrubber, demo data with planted problems, tool comparisons for 22 tools, docs 00 to 15 and reference guides. Built on shared base 1.1.1.
